# 基于 8086 汇编的俄罗斯方块课程设计说明

## 一、设计目标与环境

本项目在 IBM-PC 兼容的 DOS 实模式环境中实现俄罗斯方块，通过完整的交互程序练习 8086 指令、寄存器、段地址、数组寻址、子程序、BIOS/DOS 中断和显存访问。

| 项目 | 选择 |
| --- | --- |
| 游戏主体语言 | 16 位 8086 汇编，NASM Intel 语法 |
| 指令限制 | `CPU 8086`，避免使用 80186/286/386 才有的指令 |
| 运行格式 | DOS `.COM`，入口偏移 `0100h` |
| 汇编器 | NASM，使用 `-f bin` 生成二进制 |
| 模拟器 | DOSBox-X |
| CPU 配置 | `cputype=8086`，`core=normal`，`cycles=fixed 5000` |
| 显示 | VGA 兼容 80 列 × 25 行彩色文本模式 |
| 棋盘 | 10 列 × 20 行 |

NASM 和 DOSBox-X 分别负责“生成机器码”和“提供旧式电脑运行环境”。启动脚本属于开发辅助工具，游戏运行逻辑全部在 `.COM` 中。

源码采用 NASM 语法，不应写成“可以直接使用 MASM/TASM 编译”。如果课程强制使用 MASM/TASM，需要转换伪指令、段定义和相关汇编语法。

## 二、功能与规则

### 2.1 功能

游戏包含七种四格方块、自动下落、左右移动、顺时针旋转、软降、瞬间落底、满行消除、计分、等级、预览、落点虚影、暂停、重新开始和游戏结束。

### 2.2 规则边界

- 棋盘只保存已经锁定的方块，活动方块单独记录。
- 方块向下移动受阻时立即锁定，没有额外的锁定延迟。
- 旋转失败时，依次尝试水平位置偏移 `0、-1、+1、-2、+2`；全部失败则保持原状。
- 不实现完整 SRS、向上踢墙、暂存方块、联机、音效或最高分文件。
- 新方块在出生位置无法放入时，进入游戏结束状态。

这些规则减少了与课程核心知识无关的复杂度，同时保留了完整游戏流程。

## 三、总体结构

程序分为两个汇编源文件。`main.asm` 负责外部输入、时间与显示；`game.inc` 负责棋盘规则和数据。后者通过 NASM `%include` 合入同一个程序，最终只生成一个 `.COM`，没有额外的运行时模块。

```text
启动与初始化
    ↓
标题界面 ── 开始 ──→ 游戏运行
                         │
                    读取键盘输入
                         ↓
                    检查 BIOS 时间
                         ↓
                    更新活动方块
                         ↓
                必要时锁定、消行、出块
                         ↓
                    绘制并呈现画面
                         │
                         └──── 返回输入检查

游戏运行 ←─ P ─→ 暂停
游戏运行 ── 出生位置被占用 ─→ 游戏结束
游戏结束 ── Enter / R ─→ 新游戏
各界面 ── Esc / Q ─→ 恢复显示设置并返回 DOS
```

状态机的作用是让按键含义明确。例如空格在标题界面代表开始，在游戏运行时代表瞬间落底，在暂停时不会改变棋盘。

主循环每次最多读取一个按键，再检查时间，避免连续按键使自动下落得不到执行。画面仅在 `dirty` 标记置位时重新绘制；空闲时使用 `STI` / `HLT` 等待硬件中断唤醒。

### 主要子程序接口

| 子程序 | 输入／输出与作用 |
| --- | --- |
| `new_game` | 清空棋盘、分数和行数，重设等级与随机袋，生成方块 |
| `check_position` | `AX=x`、`BX=y`、`CL=旋转编号`、`DL=类型`；`CF=1` 表示碰撞，保留通用寄存器 |
| `get_shape` | 根据当前类型与旋转编号，返回 `DS:SI` 指向四组相对坐标 |
| `move_left` / `move_right` / `rotate_piece` | 试探并提交合法位置或旋转 |
| `step_down` / `soft_drop` / `hard_drop` | 自动下降、手动软降、瞬间落底 |
| `calc_ghost` | 将落点纵坐标写入 `ghost_y`，不修改棋盘和活动方块 |
| `lock_piece` / `clear_lines` | 将活动块写入棋盘；消行并更新分数、行数与等级 |
| `next_piece_type` | 返回 `AL=0～6` 的下一种方块类型 |
| `add_score` | 输入 `AX=新增分数`，执行饱和加法 |
| `render` | 将当前状态绘制到缓冲区并复制到显存 |

## 四、数据结构

### 4.1 棋盘：二维坐标映射到一维数组

棋盘有 200 个字节，按行存储：

```text
board[y * 10 + x]
0 ≤ x < 10，0 ≤ y < 20
0：空格
1～7：已锁定的七种方块
```

例如第 3 行、第 4 列的格子，使用从 0 开始的坐标 `(x=3,y=2)`，数组下标是 `2 × 10 + 3 = 23`。

采用一个字节保存一个格子，便于比较、复制和设置颜色。界面边框不放入棋盘数组，边界由碰撞检测单独判断。

### 4.2 方块：四个小格的相对坐标

每种方块保存 4 个旋转状态，每个状态保存 4 组 `(dx,dy)` 字节坐标：

```text
7 种 × 4 个状态 × 4 个小格 × 2 字节 = 224 字节
```

即使某些形状有重复的旋转状态，也保留统一的表结构，减少分支判断。当前方块保存类型、旋转编号以及棋盘上的参考位置。某一小格的实际坐标为：

```text
x = 当前参考横坐标 + dx
y = 当前参考纵坐标 + dy
```

方块类型参与形状表索引时使用 `0～6`，写入棋盘时用 `类型 + 1`，避免与空格值 `0` 混淆。

### 4.3 活动方块与已锁定方块分开

移动活动方块只需改变参考位置，旋转只需改变旋转编号；棋盘中的已锁定方块保持不变。这样不必每次移动时先从棋盘擦除旧方块，也避免碰撞检测把活动方块自己的旧位置当成障碍。

只有锁定时，才把活动方块的四个小格写入棋盘。

### 4.4 屏幕缓冲区

文本屏幕每个字符格占 2 字节：低字节是字符编码，高字节是颜色属性。整屏所需空间为：

```text
80 × 25 × 2 = 4000 字节
```

程序先在普通内存里生成整幅画面，然后一次复制到 `B800h:0000h`。这种方式减少逐个修改显存时出现的中间画面；它不是等待垂直消隐的硬件页翻转，因此不宣称完全消除撕裂。

## 五、关键算法

### 5.1 碰撞检测

碰撞检测接受一个候选位置与旋转状态，依次检查其中的四个小格：

1. 由形状表读取相对坐标，算出棋盘坐标。
2. 检查横坐标和纵坐标是否落在合法范围。
3. **确认坐标合法后**，计算 `y × 10 + x` 并读取棋盘。
4. 任一格非空则候选状态无效；四格都合法且为空才允许放入。

先检查边界、后读取数组十分关键，尤其是方块贴左墙时，参考横坐标可能通过偏移计算得到负数。不能先算成地址再读取未知内存。

左右移动、软降、自动下落、旋转、落点虚影和出生位置检查共用同一套碰撞规则，便于保持行为一致。

### 5.2 移动与旋转

移动采用“试探后提交”：生成候选坐标，调用碰撞检测，通过后才更新当前坐标。

顺时针旋转编号为：

```text
新旋转编号 = (原旋转编号 + 1) AND 3
```

先试原横坐标，再试左一格、右一格、左两格、右两格。每个候选位置都通过碰撞检测验证。失败时不修改活动方块的位置和旋转编号。

这种水平修正能支持常见的贴墙旋转，但没有为不同方块和旋转方向定义完整的 SRS 踢墙表，因此两者不能等同。

### 5.3 下落、锁定与落点虚影

自动下落和软降都尝试将纵坐标加 1；如果下方不可放入，则锁定当前方块。软降成功一格加 1 分。

瞬间落底反复尝试下降，直到下一步会碰撞，然后在最后一个合法位置锁定；成功下降的每格加 2 分。

落点虚影使用同样的下降试探，得到最后一个合法纵坐标。它仅用于显示，不写入棋盘、不触发锁定、不改变分数。

### 5.4 满行消除

方块锁定后，从底部检查各行：

1. 若一行有空格，继续检查其上一行。
2. 若一行的 10 个格子均非空，删除该行。
3. 将其上方各行向下搬移一行，清空最上面一行。
4. **重新检查当前行号**，因为从上方搬下来的行也可能是满行。

不能消掉一行后直接跳到上一行，否则相邻的满行可能漏消。完成扫描后，根据本次消除的总行数统一计分。

### 5.5 七袋随机出块

一袋初始包含七种方块类型各一个。使用 Fisher–Yates 洗牌：从袋尾向前遍历，每次与当前位置之前的一个伪随机位置交换。随后顺序取出，袋用完再重新填充并洗牌。

这种方法保证每组七次出块包含全部七种类型，减少某一种方块长期不出现的情况。随机数用于游戏体验，不承担密码学用途，也不宣称严格均匀或不可预测。

### 5.6 计分、等级与防溢出

一次消除 `1、2、3、4` 行，对应基础分 `100、300、500、800`，再乘以**本次消行前的等级**。因此某次消行同时触发升级时，这次奖励仍按原等级计算。

```text
等级 = min(20, 累计消行数 / 10 的整数商 + 1)
下落间隔 = 10 - min(等级 - 1, 8)    ; 单位：BIOS 节拍
```

分数和累计消行数是 16 位无符号量，最大为 `65535`。加法若超出表示范围，应保持 `65535`，而不是发生回绕。例如 `65530 + 10` 的结果保存为 `65535`，不会显示 `4`。

## 六、底层接口与汇编知识点

### 6.1 DOS `.COM` 与段寄存器

`.COM` 是没有 EXE 文件头的二进制程序。DOS 将其放到程序段内的偏移 `0100h` 处，所以源码使用：

```asm
CPU 8086
BITS 16
ORG 100h
```

`ORG` 是汇编期地址计算指令，不是在 CPU 上执行的机器指令。程序初始化数据段与栈，并为绘图访问设置显存段。近调用 `CALL` 和 `RET` 通过栈保存及恢复返回地址，子程序应按接口约定保存需要保留的寄存器。

这部分可对应课程中的段地址、偏移地址、逻辑地址、栈和子程序知识。

### 6.2 键盘：BIOS `INT 16h`

主循环先使用非阻塞检查判断是否有按键，再读取。若每轮都使用阻塞读取，程序就会停在等待输入处，方块无法在不按键时自动下落。

方向键通过扫描码识别；字母键通过字符码识别。输入逻辑还要检查当前游戏状态，避免暂停时移动方块。

### 6.3 时间：BIOS `INT 1Ah`

读取系统时钟节拍，将当前时间与上次下落时间比较。节拍达到下落间隔后执行一次下落。BIOS 时钟约为每秒 18.2 个节拍，使用它比固定次数的空循环更容易保持稳定的游戏速度。

本程序用 `DX` 的低 16 位与 `last_tick` 作减法，无符号差值允许跨越低字的自然回绕。BIOS 报告午夜归零时，重新设置基准。暂停切换、开始、重开以及手动下落后都会重设基准，避免沿用不合适的下落时间。

### 6.4 画面：文本显存与 `REP MOVSW`

80 列文本模式中，第 `row` 行、第 `col` 列字符格的字节偏移为：

```text
offset = (row × 80 + col) × 2
```

彩色文本显存段地址为 `B800h`，对应实模式物理地址 `B8000h`。缓冲区绘制完成后，核心复制方法如下。此处是原理片段，寄存器保护以实际源码为准：

```asm
; DS:SI 指向 4000 字节屏幕缓冲区
mov ax, 0B800h
mov es, ax
xor di, di
mov cx, 2000           ; 4000 字节 = 2000 个字
cld                    ; 字符串操作向高地址前进
rep movsw              ; DS:SI -> ES:DI
```

`CLD` 清方向标志，`MOVSW` 每次复制一个字，`REP` 按 `CX` 的次数重复。这一段同时体现段寄存器、串操作、方向标志与循环计数。

### 6.5 显示设置与退出

BIOS `INT 10h` 用于设置文本模式及控制光标。退出路径负责恢复显示设置，再通过 DOS 服务结束：

```asm
mov ax, 4C00h
int 21h
```

不要用无限循环或直接跳回未知地址代替退出，否则可能把模拟器留在无法正常操作的状态。

## 八、答辩常见问题

**1. 为什么不用 C 语言画界面，只把一部分逻辑写成汇编？**

本项目要练习完整的 8086 程序，游戏输入、数据、规则和显示都在汇编中完成。宿主机上的脚本只负责调用汇编器和模拟器。

**2. 一个方块怎么存？为什么不存一张图片？**

每个方块由四个小格组成，保存四组相对坐标就能用于绘制和碰撞。这样内存小，而且同一份形状数据可服务多种逻辑。

**3. 怎样判断一块能不能移动？**

先生成移动后的候选位置，逐一检查四个小格是否越界、是否与棋盘非空格重叠；全部通过才修改位置。

**4. 为什么活动方块不直接写入棋盘？**

否则移动前需要擦除旧位置，还容易让碰撞检测撞到自己。将两者分开后，只有锁定时才修改棋盘。

**5. 连续满行为什么不会漏消？**

消行并向下搬移后继续检查同一行号，保证刚搬下来的满行也被检测。

**6. 为什么不使用空循环延时？**

空循环时间随模拟 CPU 速度变化。使用 BIOS 时钟节拍，游戏下落速度主要由时间差决定，更容易解释与调整。

**7. 为什么文字能直接写到显存？**

该 DOS 实模式显示环境把彩色文本屏幕映射到 `B800h` 段。每个字符格由字符码和属性两个字节组成，写入对应地址即可改变显示。

**8. `REP MOVSW` 为什么复制 2000 次，不是 4000 次？**

整屏有 4000 字节，而 `MOVSW` 每次复制一个字，即 2 字节，所以重复 2000 次。

**9. 七袋随机和每次直接随机有什么区别？**

七袋随机保证每七次出块中七种类型各出现一次；独立随机不能保证这一点，可能很久不出现某一种形状。

**10. 这个项目是否完整遵守现代俄罗斯方块规范？**

没有。这里采用适合课程讲解的规则，缺少完整 SRS、锁定延迟和暂存等机制，答辩时应直接说明具体范围。

**11. “16 位”是否代表任意指令都能在 8086 上执行？**

不是。后续 x86 CPU 也支持 16 位代码，但增加了新指令。因此除了 `BITS 16`，还通过 `CPU 8086` 限制指令，并使用 DOSBox-X 的 8086 CPU 配置运行。

**12. 分数为什么上限是 65535？**

因为使用一个 16 位无符号字保存。程序采用饱和处理，避免继续加分时溢出回绕；如果需要更大的分数，可改为双字存储并编写多字加法和十进制显示。
